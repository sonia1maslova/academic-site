当一项脑影像（fMRI）或人类颅内脑电（sEEG）研究进入多脑区、多频段、多参数对比阶段时，把成百上千张高清渲染图直接塞进主分析代码仓库往往会带来几个痛点：Git 历史迅速膨胀、代码 diff 杂乱，而且合作者为了横向对比不同脑区或不同平滑核的结果，不得不反复下载压缩包。

## 轻量级的双仓库拆分实践

在最近的科研项目实践（如 `seeg_navigation` + `seeg-navigation-figure-gallery` 以及 `neural-pleiotropy-figure-gallery`）中，将**可复现分析代码**与**静态图表画廊**拆开维护带来了很顺畅的体验：

1. **代码与清单仓库**：专注管理分析与绘图脚本、最小环境配置（`environment_minimal_used.yml`）、数据清单及源码哈希快照，不堆积大体积二进制图片。
2. **静态图表画廊仓库**：直接镜像 `figures/` 目录树并生成静态索引，托管在 GitHub Pages 上，支持多级目录导航、标签过滤和大图对比查看。

```text
project_root/
├── codes/              # 受版本控制的分析与绘图脚本
├── data_manifest.md    # 明确记录输入文件来源与校验
└── figures/            # 经脱敏检查后选择性同步至公开图表画廊
```

## 公开前的安全与规范检查

- 确认文件名、坐标轴标签与图注中不包含任何被试身份标识、受保护临床信息或私有路径。
- 在每次代码快照中同步写清统计约定、FDR 规则以及可复现边界。
- 图表画廊用于提升审阅与交流效率，始终与可独立运行的绘图脚本和锁定依赖环境配合使用。
